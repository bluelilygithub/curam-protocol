## 2. Differences between the code and SPEC.md (code wins; flagged)

1. **Settings is a view, not a drawer** (changed at the owner's request for the Graphics-style layout). The addendum's "settings drawer moves behind Settings" is already true in spirit.
2. **The main screen is a job dashboard**, not two drop zones (owner's request). This conflicts with addendum §6.3 — see decision D1.
3. **Inside Vault the app loads Vault's font from Google Fonts** (owner's request for Vault styling). SPEC §9 "no network after load" now holds for the standalone build and for file handling, not for the embedded font.
4. **Severity extras not in SPEC**: a wording change that drops a large part of a paragraph is High; removed table rows are grouped into one change; table column-count changes are formatting.
5. **No MinHash** (exact Jaccard is fast enough: 96,000 words compared in under 1 s).
6. **PDF text position is not compared** (layout pixel diff covers it); merged DOCX table cells are not compared.
7. **A "review for the author" PDF exists** that SPEC did not ask for; the addendum's report changes (§8) should extend both PDFs.

## 4. Decisions needed before building (the addendum's "get approval first")

- **D1. Main screen.** Addendum §6.3 wants a bare screen (two drop zones, optional word limit, a big Check button) with settings hidden. The page now has the Graphics-style tool list and job dashboard you asked for. Proposal: keep the Vault shell, make **Check a document** the first and largest job (verdict-first flow), and show the verdict and review queue as the first tool after checking; the current views move under "Show all changes".
- **D2. Where projects live.** The addendum stores projects, rounds and files in the browser's IndexedDB (files never leave the computer, but a cleared browser loses them; export is the backup). Vault's normal pattern is server storage per user (Postgres + uploads), which survives browsers and devices but means the files *do* leave the computer. Proposal: IndexedDB as the addendum says, with the export reminder; server storage could be an opt-in later.
- **D3. Restructures the audit finds necessary** (approval asked now): (a) `App.tsx` state moves into a small store so the review queue, projects and the existing views share one comparison result; (b) `authorReport.actionFor()` moves into `messages.ts`; (c) the pipeline gains a post-processing stage for the new checks (§4–5) instead of growing `content.ts`. No reader or comparison module is rewritten.
- **D4. Re-tiering changes existing results** (§3): typo and formatting stay info; moved becomes amber (it is Medium today, same); per-section word drop >15% becomes red (new). Test expectations that change will be listed in that commit.
- **D5. Spelling list.** The ~300 AU/US pairs have to be curated (no network to fetch one). I would write the list from standard references and keep ambiguous words out; it can be reviewed as a plain JSON file.

### Decided (owner, 2026-11-21)

- **D1:** keep the Vault shell (tool list, job screen); add "Check a document" as the first and largest job; after checking, the verdict and review queue show first and today's views move under "Show all changes".
- **D2:** projects live in the browser (IndexedDB) as the addendum says, with export/import and the export reminder.
- **D3:** restructures approved. (a) the shared results store is done in Phase 2, where the review queue first needs it; (b) and (c) are done in Phase 1.
- **D4, D5:** as proposed. Phase 1 approved.

## 6. Follow-up, 2026-11-26: Unicode PDFs and the Railway build

### Unicode fonts in the exported PDFs (done)

The Latin-1 limitation is gone. Both PDFs (the comparison report and the review for the author) now embed **Liberation Sans** (Helvetica's metrics, so the look and line breaks are unchanged) and, only when the text needs it, **Droid Sans Fallback** for Chinese, Japanese and Korean. Characters Liberation lacks are drawn in the fallback font run by run; CJK text wraps between characters, and tables size their columns properly. Curly quotes, en and em dashes, non-breaking spaces, arrows, accented names and CJK all print; nothing becomes "?". Code: `src/report/pdfFonts.ts`; fonts and their licences in `src/report/fonts/`. Details in `docs/doc-compare.md` (PDF fonts).

- **Bundled, not fetched:** the fonts are lazy chunks of the app itself. No request goes to another site, and the single-file build inlines them (works from disk). The no-network test still passes, and a new test checks that exporting both PDFs makes no `fetch`/`XMLHttpRequest` call.
- **Bundle size:** main chunk unchanged (2,773 KB to 2,777 KB). New lazy chunks: Liberation Sans regular, bold and italic, about 1.65 MB in total (775 KB gzipped), loaded on the first PDF export; Droid Sans Fallback 5.25 MB (2.2 MB gzipped), loaded only when the report contains text Liberation cannot print. Built output on disk 13 MB to 26 MB (about half of the increase is source maps of the font chunks). Single-file build 3.0 MB to 10.1 MB.
- **Changed behaviour:** `buildReportPdf`, `buildAuthorPdf`, `exportPdf` and `downloadAuthorPdf` are async; if the fonts cannot load (for example a tab left open across a deploy) the person gets a message instead of a button that does nothing. Two test expectations changed because the characters now print: the watermark reads "UNRESOLVED ISSUES — NOT READY TO SUBMIT" (was " - "), and the number instruction reads `"30" → "60"` (was `->`).
- **Limits:** the CJK font has one weight, so bold CJK prints regular. The word diff in the review for the author shows quotes and dashes as the comparison normalised them (straight), as before; the Original and Edited text keeps them curly.
- **Tests:** 225 (219 before, plus 6 in `tests/unicodePdf.test.ts`: both PDFs with curly quotes, em and en dashes, accented names and Chinese and no "?", the CJK font only when needed, CJK wrapping, table column widths, no network).

## 7. Follow-up, 2026-11-26: web pages for copywriters

Built on branch `doc-compare-web-pages`. A copywriter can fetch a web page by its address (inside Vault) or choose a saved `.html` file, keep it as a project's dated original, download it as Word, add the edited `.docx` as round 1, and later fetch the published page as a new round. Details in `docs/doc-compare.md` (Web pages).

- **Supported formats** are now PDF, Word (.docx), web page (.html, .htm), Markdown and plain text. A web page and a Word file may be compared with each other; every other pair must be the same type.
- **Privacy promise, the one exception:** Fetch a web page sends only the typed address, from Vault's page (not the app), to `POST /api/doc-compare/fetch` (logged-in users only, behind the docCompare flag, SSRF-guarded by `safeFetch`, 30 per person per 10 minutes). Files, drafts and results still never leave the browser, and the standalone build has no URL option. A hostile page is parsed, never rendered: no script runs and nothing it names loads (tested in jsdom and checked in real Chromium under Vault's production CSP: no request to the page's hosts, no script ran).
- **Checked end to end** in the production Docker image with real Chromium: fetching gov.uk, the ATO and Basecamp pages created the project, the Word download read back as "No significant changes found" in round 1, the only fetch requests came from Vault's page with `{ "url": … }` as the whole body, and there were no CSP violations or console errors. Eight real pages round-trip through Word with no change reported.
- **Found and fixed on real pages:** Vault's CSP (`base-uri 'self'`) applies to parsed documents too, so the reader keeps links as written instead of setting a `<base>`; the DOCX reader dropped the `#fragment` of a link (Word keeps it in `w:anchor`); the terms check called an acronym "new" when the original used it only in the plural ("NETPs") or before a hyphen ("IGST-"), a bug for every format; a web page against a Word file no longer flags file size and internal dates.
- **Deploy:** `doc-compare/package.json` gained `@mozilla/readability` and moved `docx` to dependencies, so the base image rebuilds (10 to 15 minutes). `scripts/buildDocCompare.js` now installs when any declared package is missing (not only vite), so the first deploy on the old base installs Readability (about 2 s, checked in Docker) instead of showing "DocCompare is not available".
- **Tests:** 246 in `doc-compare` (225 before; `tests/webPages.test.ts` adds 21: the reader on realistic and hostile pages, HTML vs HTML, HTML vs edited Word, the Word round trip, the bridge, a project with a fetched original, the real-page regressions), plus `node server/routes/docCompareFetch.test.js` (schemes, private and metadata addresses written directly and after DNS, redirects to internal addresses, size, a trickling page, non-HTML, the rate limit).
- **Known limits** are listed in `docs/doc-compare.md` (CSS not read, JavaScript-built pages, pictures by alt text only, merged cells, claims like "4.9 out of 5" not detected).
