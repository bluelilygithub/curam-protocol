# Scenario working (hand-derived expectations, C12)

Inputs are generated by `scripts/gen-scenarios.mjs`. Expected results live in `scenarios.test.ts` and were worked out
below **before** the engine was run against them. A scenario whose expectation came from the engine is invalid.

Conventions used throughout: room-local metres, +Y up, CCW polygon, interior normal = left of the edge direction. Local
frame of an object: width along local +X, length along local +Y ("front"), rotation CCW from world +X.

elevation 0.9 + 1.2 = 2.1 ≤ 2.7. **Expected: valid, zero violations.**

## door-swing-edge

- door-1: centre (2, 0), width 0.9, **left** hinge → hinge (2.45, 0). Left hinge: the leaf starts along −X (polar 180°) and
  sweeps clockwise into the room. Swing 75° → polar 105°..180°, radius 0.9. Access depth 0.3 → annulus r 0.9..1.2.
- chair-a 0.4 square at (2.65, 0.2): x 2.45..2.85. The sector lies at x ≤ 2.45 (its east-most point is the apex), so the
  gap on the X axis is exactly 0 → touching → valid.
- chair-b 0.2 square at (2.0, 0.25): relative to the hinge corners are (−0.55..−0.35, 0.15..0.35): max radius 0.652 < 0.9,
  polar angles 135°..165° → entirely inside the sector, not in the access annulus. **Hard `door_swing` [chair-b, door-1].**
- door-2: centre (1.0, 0), width 0.8, **right** hinge → hinge (0.6, 0), 90° sweep polar 0..90, access 0.3 → r 0.8..1.1.
  Point (1.6, 0.02): r = 1.0 from door-2's hinge (inside its access annulus) and r = 0.85 from door-1's hinge at polar 178.7°
  (inside door-1's sector) → overlap. **Soft `door_swing` [door-1, door-2]** only. door-2's region ends at x = 1.7;
  chair-b starts at x = 1.9, chair-a at x = 2.45 → neither touches door-2.
**Expected: valid:false; exactly the hard chair-b violation plus the soft door-vs-door violation.** Remove chair-b → valid:true.

## wall editing arithmetic (M3; `tests/unit/wallEdit.test.ts`, `tests/interaction/m3gates.test.ts`)
Room 4 × 5 (v1 (0,0) v2 (4,0) v3 (4,5) v4 (0,5); w1 floor, w2 right L 5, w3 top, w4 left).
- **Clamp:** window width 1.2 on w2 at 2.5. Move v3 to (4,2): L = 2, legal centre range [0.6 + 0.05, 2 − 0.65] = [0.65, 1.35] → 1.35. At L = 1 the wall is shorter than 1.2 + 0.1, so it cannot be clamped and stays 2.5 (then `fixture_out_of_wall`).
- **Insert** on w1 at (1.3, 0.4): projected to (1.3, 0), first half L1 = 1.3. A window at 2.5 has its centre past L1 → new segment, offset 2.5 − 1.3 = 1.2; a door at 0.9 stays. Delete the corner again: 1.2 + 1.3 = 2.5, geometry identical.
- **Delete v3** (rectangle → triangle): incoming w2 (L 5) merges into v2 → v4, the diagonal √(4² + 5²) = 6.4031. A window at 2 on w3 becomes 2 + 5 = 7, re-fitted to hi = 6.4031 − 0.6 − 0.05 = 5.7531 → 5.753.
- **Wall length:** floor wall 4 → 5 moves v2 to (5, 0). A 3-4-5 wall (0,0)→(3,4) set to 10 puts its end at (6, 8).
- **Stick:** dragging v3 straight down from (4,5): v3 reaches v2's position at y = 0 (degenerate), so the last valid millimetre is y = 0.001 (edge v2→v3 of 1 mm is allowed).
- **Impact:** v3 → (4, 4.2) and v4 → (0, 4.2) (the `wall-edit-cascade` scenario): sofa (y 4.05..4.95) crosses the new wall, chair (y 4.35..4.85) is outside, table (touching y = 4.2) is fine → exactly `chair-1`, `sofa-1`. With only v3 moved to (4, 4.2) and the sofa at (2, 4.5): the wall runs (4,4.2)→(0,5), at x = 3.1 it is at y 4.38 → the sofa's corner (3.1, 4.975) is outside → one object.
- **Reshape (e2e/gate):** corners (0,0) (4,0) (2,2.5) (2,5) (0,5): shoelace = (0 + 10 + 5 + 10 + 0)/2 = 12.5 m². The drawn L (3 × 3 minus 1.5 × 1.5) = 6.75 m².
