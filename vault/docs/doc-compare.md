# DocCompare

**DocCompare** (AI tools menu, `/doc-compare`, flag `docCompare`, lifecycle `preview`) compares an original document with an LLM-edited version and reports every change: missing content, added content, wording and typos, number/date changes, formatting, PDF page layout and file metadata. Its main job is catching content an LLM silently skipped or altered. Built 2026-11-21 from the spec in the owner's brief.

## Where it lives

| Piece | Where |
|---|---|
| The app | `doc-compare/` — its own Vite + React + TypeScript app (pdf.js, jszip + fast-xml-parser, remark, jsdiff, pixelmatch, jsPDF). Built into `dist/doc-compare-app/` by `scripts/buildDocCompare.js` (non-fatal, like Route Tracer). |
| Host page | `client/src/pages/DocComparePage.jsx` — iframe to `/doc-compare-app/?embedded=1`; shows a "not built" notice if the app's marker tag (`name="doc-compare-app"`) is missing |
| Shared tools list | `client/src/pages/docCompare/docCompareTools.mjs` — the (i) box text (`HOW_IT_WORKS`), the guide's Open-button ids (`GUIDE_TOOLS`) and the bridge message types. The app imports it through its `@vault-client` alias. |
| Guide chat | `server/services/docCompareTutor.js` (on `guideCore.js`) + `server/routes/docCompareTutor.js` (on `guideRouter.js`), `POST /api/doc-compare-tutor` behind `requireFeature('docCompare')` and `aiLimiter`; wrapper `client/src/pages/docCompare/DocCompareTutorChat.jsx`; registry id `doc-compare` |
| Tests | `cd doc-compare && npm test` (readers, aligner, classifiers, severity, an end-to-end test per generated fixture pair, the guide bridge, and a test that fails if `fetch`/`XMLHttpRequest` is called during a comparison); `node server/services/docCompareTutor.test.js` (guide drift, no model) |

## Privacy: files never leave the browser

The app reads and compares both files inside the iframe. It makes **no network calls** after loading: the pdf.js worker and the comparison worker are bundled inline (blob URLs, allowed by the CSP's `worker-src 'self' blob:`), no fonts or CDNs are fetched, and nothing is saved except the person's Settings in `localStorage` (`doc-compare:settings`, `doc-compare:info-seen`). Only the guide chat, which lives in Vault's page outside the frame, calls the server, and it never sees the files or results. Do not add an API call to the app.

## How it works (short)

1. **Gate 1, file type** (`src/checks/fileType.ts`): magic bytes (`%PDF`, ZIP containing `word/document.xml`), extension for `.md`/`.txt`. Different types, unsupported, legacy `.doc`, damaged, password-protected and scanned (no text layer) files stop with a plain message.
2. **Readers** (`src/readers/`): each returns a `NormalizedDoc` (blocks with runs and locations, plus metadata). DOCX is read directly from the XML (not mammoth) so fonts, sizes and styles survive; theme fonts are resolved. PDF lines are grouped into paragraphs by spacing, headings by font size, and paragraphs that run over a page break are rejoined. A new file type is one new reader in `registry.ts`.
3. **Gate 2, same document** (`src/checks/similarity.ts`): 40% headings, 40% word 5-gram overlap, 20% structure; below the threshold (60) the person can Cancel or Compare anyway (recorded in the report).
4. **Compare** (in a Web Worker): LCS over block fingerprints, fuzzy pairing between anchors, moves, grouped removed sections and table rows, word diffs classified as number / typo / wording, formatting by character range, metadata flags. Severity rules are all in `src/report/severity.ts`.
5. **PDF layout** (main thread, after the results show): pages rendered at 1× and compared with pixelmatch; over 0.5% changed is a Layout change. The viewer renders at 1.5×.

## Page layout (like Graphics and Video Tools)

`DocComparePage.jsx` draws the shell with Vault's shared pieces: `ToolSidebar` on the left (six tools in three groups: Compare documents; Changes, File details, PDF pages; PDF report, Settings — a results tool shows "Compare two files first" until there are results), the `JobStart` "What do you want to do?" screen with seven jobs (`DOC_COMPARE_GOALS`), and `BackToJobs` + `JobBar` above each tool. The app in the frame is the tool content: each tool is a view of the app (`doc-compare/src/ui/App.tsx`), and the frame stays loaded while switching, so files and results survive (also going back to the job screen). A job step can preset the Changes filters (`filter: { categories, severities }`), and when Compare finishes during a job the page moves on to the job's next step by itself. Standalone (not in Vault) the app shows its own header and tabs instead. Bridge messages: `doc-compare:view` (Vault → app: show a view, optional filter), `doc-compare:open` (the guide's Open buttons), `doc-compare:context` (app → Vault: current part, view, whether there are results / PDFs, and `cause: 'self'` when the app changed view by itself so the tool list follows).

## Submission-check addendum (all six phases done)

The owner's addendum turns DocCompare from "show me the differences" into "is this ready to submit?". The audit and the phase plan are in `doc-compare/docs/AUDIT.md` (decisions: keep the Vault shell and add a "Check a document" flow; projects in the browser's IndexedDB). **Phase 1 (done):** every change carries `tier` (red/amber/info = high/medium/low), a plain-language `summary`, `whyItMatters`, `action` and `origin`, all worded in one catalogue, `doc-compare/src/report/messages.ts` (Australian English; a test forbids "safe", "correct" and "verified"). Re-tiering: layout pixel changes and file-detail warnings are now info; a section losing more than 15% of its words is red (`compare/postChecks.ts`). The review for the author prints "Why it matters" under each action.

**Phase 2 (done): verdict first.** The start screen leads with "Is it ready to submit?" and a **Check a document** button (job `check`: Compare documents → Verdict and review). After comparing without a job, the page opens **Verdict and review** (`doc-compare/src/ui/ReviewView.tsx`): a banner — Not ready to submit (a red item open or marked Fix later) / Review recommended (amber open) / No significant changes found — a one-sentence summary, the accuracy note ("This check shows what changed … It doesn't check whether the content is accurate."), progress, and a card per red and amber item with what happened, why it matters, the text, and Restore (copies the original text to the clipboard) / Accept / Fix later (red) or Accept / Dismiss all similar (amber), Undo, and R/A/L and arrow-key shortcuts. Rules in `src/review/verdict.ts`. Decisions are kept in the browser's IndexedDB (`doc-compare` database, `decisions` store), keyed by the SHA-256 of both files, so a reload or re-running the same files keeps them; item keys come from the change's content, not its number. The old Changes tool is now **All changes**. The comparison report opens with the verdict, the summary, the accuracy note and a decisions table, then "Full detail"; while any red item is open or marked Fix later every page carries an "UNRESOLVED ISSUES — NOT READY TO SUBMIT" watermark (cannot be turned off). The review for the author leaves out accepted changes and says how many. The different-documents warning now reads "These look like different documents (only 2 of 14 headings match) Check you've picked the right files." The tour has 13 steps (adds the panel and the verdict).

## Submission checks (addendum phase 3)

Run after the block comparison by `runPostChecks` (`doc-compare/src/compare/postChecks.ts`), one module each in `doc-compare/src/checks/`:

- **New claims** (`claims.ts`, red): in added paragraphs, and in the inserted words of changed ones, any statistic (percentage, money, a number with a unit such as "1,200 households", "since 2019"), citation (`[3]`, `(Smith et al., 2021)`, `Smith (2021)`), link or DOI, source ("a 2021 survey by the Housing Research Centre", "according to …") or quote of 4+ words that is nowhere in the original. A figure that replaced a figure stays a Number change; a quote resembling an original one is the quote check's job. One item per distinct claim.
- **Quotes** (`quotes.ts`, red): quotes of 4+ words in double or curly quotes, Markdown block quotes and Word "Quote" styles must appear exactly (after trivial normalisation). Reworded (with a word diff) or removed; not reported when the whole paragraph was removed (already red).
- **Word and page limits** (`limits.ts`, red): word limit on the Compare documents screen and in Settings, page limit in Settings; the reference list is left out by default. `ComparisonResult.words` holds the totals and per-section counts (verdict screen, File details "Words by section", report page 1).
- **Required headings** (`headings.ts`): a list pasted in Settings (templates saved in localStorage `doc-compare:heading-templates`); missing is red, out of order amber; without a list nothing extra (removed headings are already reported).
- **Version number** (`version.ts`): "Version 1.3", "v1.3", "Rev B", "Draft 4" in the first 40 blocks / two pages, and a version-history table. Content changed but version did not, or version changed without content change, or it disappeared: amber; it went backwards: red; history table not extended: amber.

Two new jobs (invented facts and quotes; within the word limit). Tests `tests/phase3.test.ts` and the uc03/uc04/uc05/uc06/uc11 fixtures.

## Submission checks part 2 (addendum phase 4)

Readers now carry `NormalizedDoc.notes` (footnotes, endnotes, Markdown link definitions; ids `fn:2`, `en:1`, `link:x`), `Block.notes` (the notes a block points to) and `Block.number` (an automatic list number as shown). DOCX reads `word/footnotes.xml`, `endnotes.xml` (labelled in order of first mark, as Word shows them) and `numbering.xml` (counters per list, `%1.%2.` level text, decimal/letter/roman, bullets give no number). Markdown reads `[^n]` footnotes, reference links and ordered-list numbers (start + position). PDF, best effort: small text in the bottom fifth of a page starting with a number is a footnote, a small number in a body line is its mark (taken out of the text); `notesBestEffort` is set and every reference/citation item from a PDF says "(PDF: found by best effort)".

- **References** (`checks/references.ts`): entries from the reference list (by heading; a PDF paragraph with several `[n]` entries is split) and the notes, matched by fingerprint (text without its number and link, Dice ≥ 0.85, best first). Removed / added / changed (authors, year, title, link) are red; added ones count as claims in the verdict sentence. A renumbered list is amber. Citations (`[3]`, `[2–4]`, `(Smith et al., 2021)`, `Smith (2021)`, footnote marks) that point to nothing are red, unless they already did in the original or are reported as an invented citation; the same paragraph citing a different source, or a citation taken off its text or moved onto other text, is red. Paragraphs in the reference list are left out of the paragraph comparison (`pipeline.ts`), so a removed reference is one item. File details gain References and Footnotes and endnotes rows. Footnotes count towards the word total (Settings, on by default).
- **Numbering** (`checks/numbering.ts`): numbers from `Block.number` or the text (`1.`, `2.3`, `(a)`, `(iv)`, `[3]`, `Figure 2`, `Table 3`); lists restart under each heading, headings, figures and tables run through the document. A gap, repeat or step back the original did not have is amber; paragraphs whose number changed are one amber item with a child each. A paragraph whose only change is its leading number is no longer a Number change (`content.ts`).
- **Spelling** (`checks/spelling.ts`, list `checks/spellingList.json`: about 285 entries: -ise, -yse and -our stems, expanded to their usual forms, plus whole-word pairs; program/programme, licence/license, practise, judgement, inquiry/enquiry and other ambiguous words left out). The standard is whichever the original uses more (outside quotes and the reference list); a tie means no check. Each word that switched is a child of one amber item.
- **Terms** (`checks/terms.ts`): defined terms (`"X" means`, `(the "X")`), acronyms with an expansion whose initials match, capitalised phrases used 3+ times, and **Protected terms** from Settings (typed or loaded from a .txt file). Amber when a term is no longer used or used less than half as often, an acronym loses its expansion, or a new acronym is never spelled out (a short list of well-known ones is exempt).

Review cards for grouped items (spelling, renumbering) list the children. Two new jobs (references and citations; spelling and terms); the structure job also shows numbering. Tests `tests/phase4.test.ts` and the uc07 (figures), uc08 (references, footnotes), uc10 (numbering) and uc12 (spelling, terms) fixtures. Changed expectations: removing a numbered heading or section now also reports the gap in the heading numbers (section-removed, uc03-heading-removed).

## Projects and rounds (addendum phase 5)

With **Save this as your original?** ticked (under the file boxes, ticked by default once an original is chosen), Compare creates a **project**: the original is kept as a clean copy and the edited file is round 1. Unticked, the comparison is a one-off kept under Saved checks, as before. Code in `doc-compare/src/project/`; stored in IndexedDB (`doc-compare` v3, store `projects`, one record per project with its files as Blobs).

- **Rounds** (`engine.addRound`): inside a project, Compare documents shows the original as kept, **Add the latest version (round N)**, an optional note and **Check this version**. Gates 1 and 2 still run. A file whose SHA-256 matches the original or a round is refused ("This is the same file as round 3"). Each round is compared with the **accepted state** and with the previous round only, so cost does not grow with rounds; old rounds are never compared again.
- **Accepted state** (`accepted.ts`): the current original plus every accepted change since it became the original, applied as edits (`Change.edit`: remove / insert after / replace, by the original's block ids; inserted blocks are named after their anchor). Rebuilt when needed, never stored; the stored original is never edited. An accepted paragraph is held back while a red claim or quote in the same paragraph is open.
- **Identity and statuses** (`track.ts`): `itemId` = the change's anchor in the original (`Change.anchor`: block id, or `+<preceding block>:<fingerprint>` for added text) + its kind (wording / typo / number count as one "text" kind); checks without an anchor use their description (counts left out for word limit, version, spelling, terms, metadata). The content key tells "changed again" apart. Statuses: new, open, notFixed ("You chose to restore this in round 2, but it's still missing." — shown red), changedAgain, accepted (closed, not asked again), fixed (closed, "Fixed in round N"). Open items from an earlier round carry a drift note ("This paragraph from your original was removed in round 1 and hasn't come back."). The queue puts not fixed and new first; fixed and accepted go under **Resolved** (with Undo acceptance). The verdict comes from the items against the accepted state. **This round only** shows the comparison with the previous round, read-only.
- **Decisions**: any decision in the latest round; in an earlier round only undoing an acceptance, which re-checks the latest round. Changing Settings re-checks the latest round. A project keeps its own word limit, page limit, required headings and protected terms.
- **Timeline** (tool): one row per round (date, note, words as on the verdict screen, sections, references, fixed / not fixed / new, red / amber / info, verdict), the round that lost the most words marked; press a round to open it (read-only). **Delete** removes a round and every later one. **Make round N the new original** (latest round, file kept): reason required, open red items listed and accepted as part of it ("absorbed"); the old original goes to Earlier originals; the timeline and the report always show it. **Compact old rounds** drops the files of all but the last two rounds (originals keep theirs); "File not kept".
- **Projects** (tool, home screen): name, original, rounds, updated, size, exported, latest verdict; Open, Rename, Export, Delete (Yes/No), Import project (same id: Keep both / Replace), New check. Warnings at 80% of the browser's storage quota (`navigator.storage.estimate`) and for a project over 200 MB (`PROJECT_WARN_MB`). The reminder "Your browser can clear saved files. Export your project to keep a copy." shows at the start and every 5 rounds without an export.
- **Export / import** (`transfer.ts`): `<name>.doccompare`, a zip of `manifest.json` (format, version, the project with dates as ISO strings) and `files/<sha256>`. Import validates the format and refuses anything else with a plain message.
- **Report**: for a project round, page 1 names the project and round and gives the round summary; then a Timeline table and every replacement of the original with its reason and absorbed issues, before "Full detail".

Vault: tools Projects and Timeline, "Or open a project" on the start panel, job "Check a new draft of the same document", guide ids projects, save-project, add-round, timeline, new-original, compact, round-summary, resolved. Tests `tests/projects.test.ts`.

## Intentionally different versions (addendum phase 6)

For two versions meant to differ (a long and a short one, for government and for industry), tick **These are intentionally different versions** in Compare documents. One-off comparisons only: it unticks and disables "Save this as your original?", since project rounds always get the full review. The drop zones become Version A and Version B, and the same-document warning appears only below 30 (`VERSIONS_SIMILARITY` in `settings.ts`). The comparison is the usual one plus `ComparisonResult.sections` (`compare/sections.ts`): each section is in both versions, worded differently (with how alike, 0-100; a renamed heading is matched by its text, Dice >= 0.5), only in A or only in B. Verdict and review shows a **Version comparison** (`ui/VersionsView.tsx`): no verdict and nothing to decide, the numbers and quotes that differ listed to check ("A figure differs in …"; `stillCheck`), and the sections grouped. The PDF report is titled "Version comparison" (sections table, numbers and quotes to check, then Full detail; no verdict, no watermark; file `version_comparison_…pdf`), and there is no review for the author. A saved check remembers the mode and keeps no verdict. Vault: job "Compare two versions meant to differ", guide id `versions-mode`. Tests `tests/versions.test.ts`.

## Labels and saved checks

Compare documents has an optional **Label** box above the file boxes. Every successful comparison is saved, under that label (or "<edited file name> · <date>"), in the browser's IndexedDB (`doc-compare` database v2, store `checks`; `src/review/savedChecks.ts`, shared opener `src/review/db.ts`). A saved check holds the label, dates, both files (as Blobs), the pair key, and the latest verdict and decided count (kept in step as decisions change). One saved check per pair of files: comparing the same two files again updates it. **Saved checks** (a tool in the Compare group, also "Or open a saved check" on the start panel) lists them newest first with search (label and file names, every word must match), Open (rebuilds the files, re-runs the comparison; decisions come back because they are keyed by the same file hashes), Rename, and Delete (inline Delete? Yes / No; removes the check, its files and its decisions; no recycle bin, since it is browser storage). Nothing is uploaded: another browser or computer does not see them, and clearing site data removes them. Projects with rounds and export/import (addendum phase 5) will build on this. Test `tests/savedChecks.test.ts`.

## Review for the author

**Download review for the author** (top of the PDF report tool, and on the Comparison done card) makes `review_<edited name>_<date>.pdf` in the browser (`doc-compare/src/report/authorReport.ts`, jsPDF): a to-do list to send back to whoever made the edit. It always covers **every** non-trivial change, whatever filters are set (trivial differences are only counted; file details only when flagged Medium or High), sorted into Must fix / Please review / Minor with a count box on the cover. Each item has a tick box, its location, one plain instruction from `actionFor()` ("Restore the missing section …", "Check the changed figure: "30" -> "60" …"), and the text: the word diff with removed words red and struck through and added words green and underlined, a missing section's contents listed once, or the text once when only its place or formatting changed. Footer "Page n of N". Test: `tests/authorReport.test.ts` (reads the generated PDF back with pdf.js). The comparison report (`pdfExport.ts`) is still there, for the person's own records, and follows the filters.

## Menu placement

A new tool only appears where the admin's saved menu layout puts it (Settings → menu layout, `workspace_settings.nav_layout`); otherwise it lands in an "Unsorted" group. `server/services/navSeed.js` (run on boot from `db.js`) places each item in `NEW_NAV_ITEMS` into the saved layout **once**, next to a neighbour (DocCompare goes after Contract Review), and remembers it in `nav_layout_seeded`, so an admin who later moves it back to the pool is not overruled. Test: `node server/services/navSeed.test.js`. Add the next new tool to `NEW_NAV_ITEMS` the same way.

## Look

Inside Vault the app wears Vault's chosen theme and font (`doc-compare/src/ui/theme.ts`, the same approach as Route Tracer: reads the same-origin `vault-settings` key and Vault's own `client/src/themes.js`, sets the `--color-*` variables and `--font-sans`, follows changes from other tabs). Buttons, inputs and chips use Vault's sizes (text-sm, medium weight, rounded-lg, opacity hover, 200 ms). Only when embedded: the font is a Google Font, so loading it is a network request for the typeface (never anything about the files; Vault's page already loads it). The standalone single-file build stays fully offline with system fonts and its own light/dark palette.

## Known limits

- PDF report fonts are Latin-1 only: other characters print as `?`.
- PDF text position (the transform matrix) is not compared; the page pixel diff covers layout. Merged table cells are not compared.
- Similarity uses exact shingle Jaccard (no MinHash); fine to a few hundred thousand words.
- Tested on generated fixture documents and a synthetic 200-page DOCX (under 1 s); not yet on real AI edits or on Railway.
- `npm run build:single` inside `doc-compare/` makes a one-file `dist/index.html` that opens from disk (not used by Vault).
