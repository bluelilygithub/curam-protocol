# Notes

Page `client/src/pages/NotesPage.jsx` (`/notes`), API `server/routes/notes.js` (`/api/notes`), table `notes`. Private to the person who wrote them (no sharing). Voice notes: `docs/voice-notes.md`.

## What it does

- **List**: `GET /api/notes` sends a short `preview`, never the whole text; 100 at a time (`X-Has-More`). Filters: search (title, text, project, client, tag, file name, text inside files), date range (edited or created), project, client, files (`files=with|without`: has / has no attached files, `noteQuery.js`; also in saved views and "This list" in Ask), tags (a note must have ALL picked tags), `untagged`. Group by Date, Project, Client or Tag (`client/src/pages/notes/noteGroups.mjs`, pure and tested). Pinned notes lead in their own section.
- **Editor**: autosave (queued, flushes on switching notes / hiding the tab), Write / Preview (markdown through the shared `react-markdown`; tick-boxes in Preview write back into the text), project and client, tags, dictation, `@` pull-ins (web, Gmail, Calendar), AI actions (summary, to-dos to tasks, tidy up, tags, title — they only propose, `server/services/noteAi.js`).
- **Rich editor (on demand)**: Write / **Rich** / Preview switch above the text (remembered per device; Write stays the default). Rich is a Tiptap editor (`client/src/pages/notes/RichNoteEditor.jsx`, lazy-loaded so Tiptap is only downloaded when someone first picks Rich; settings and the pure helpers in `richEditorConfig.mjs`): toolbar for bold, italic, strikethrough, H1-H3, bullet/numbered/to-do lists, quote, code block, divider, link, table (row/column buttons appear inside a table), undo/redo. **A note is still stored as plain Markdown** (`tiptap-markdown`), so search, Ask, Preview, AI actions, the list and the recycle bin never know which editor was used. Safety rules: (1) opening a note never saves it: the editor only reports a change after the person does something (key, paste, drop, toolbar, tick), so tidying done while it loads is never written; (2) when Rich cannot hold a note exactly (`roundTripChangesMeaning`: different words or a different number of list items/to-dos, for example one list mixing bullets and to-dos) it is read-only behind a notice with "Edit in Write" / "Edit here anyway"; (3) rewriting only happens after an edit, and normalises spacing (a blank line before a list), escapes a few symbols (`\*`, `\[`), writes `< > &` as plain characters, and writes a line break as a plain new line, not a backslash. No underline, colours or images (Markdown cannot hold them), no `@` pull-in menu in Rich (the Insert buttons in the AI menu still append), no slash menu. Tests: `richEditorConfig.test.mjs` (the same editor run headless in jsdom); tooltips for every toolbar button in `noteTips.mjs` `richBar`.
- **Chat and Notes (Notes is the foundation tool)**: Chat reads Notes **only when the person switches "My notes" on for that chat** (settings under the message box, off in every new chat, remembered per chat in `localStorage` `vault:chat:useNotes:<sessionId>`). The browser sends `useNotes: true` with each message; `POST /api/chat` then calls `findNotesForChat` (`server/services/noteContext.js`): the words of the message (`fallbackKeywords` -> Postgres full-text, which also looks inside attached files) merged with notes close in meaning when an embedding model is set up (4 s limit, then words only), at most 5 notes of 2000 characters (`LIMITS.chat` in `noteAsk.js`), **no "most recent notes" fallback** (an unrelated note is worse than none; the model is told none matched). The block goes in the system prompt just before today's date, never cached, and says note text is data not instructions. The SSE usage event carries `notesUsed: [{ id, title }]` and the reply shows "From your notes:" with each note opening in a new tab, or "No note matched this message." That list lives on the screen only (not saved with the chat). Only the person's own notes are read (`noteQuery.buildFilters` owner check); note text goes to the AI service with the message. Not used for Student Cards chats. The other direction: the pen button under any reply, and **Save chat to Notes** in the chat's menu, create a new note (`POST /api/notes`, filed under the chat's project; titles and bodies in `client/src/utils/chatToNote.mjs`, ends with "Saved from the chat ..."), with an Open button in the toast. Tests: `noteContext.test.js` (pure + database), `chatToNote.test.mjs`.
- **Phone**: the list is the whole screen; a note opens full screen with a back arrow; filters and the AI menu are bottom sheets.
- **Tags**: table `note_tags (note_id, user_id, tag)`. One rule for what a tag is (`server/services/noteTags.js`, copied in `client/src/pages/notes/noteTags.mjs`, a test keeps them equal). Rename (merges) and remove everywhere from Manage tags.
- **Templates**: built in (`noteTemplates.mjs`, filled with `{{date}}`, `{{isodate}}`, `{{weekday}}`, `{{time}}`) and the person's own (table `note_templates`, up to 50, saved from an open note). New note → From a template.
- **Saved views**: a name for a combination of search, date range, project, client, tags and grouping (table `note_views`, up to 30, unique names). The server decides what a view may hold (`server/services/noteViews.js`: known fields and values only); the browser compares and describes them (`client/src/pages/notes/noteViews.mjs`). Date ranges stay relative. A view whose project or client has been deleted drops that part with a message. Changing the filters after opening a view offers Update. The Views button sits beside Filters (`NoteViewsMenu.jsx`).
- **Reading inside files (for Ask)**: `server/services/noteFileText.js` takes the text out of an attached PDF (`utils/pdfText.js`), Word (.docx, mammoth), Excel (.xlsx/.xls), PowerPoint (.pptx, slide XML) or text/Markdown/JSON/CSV file and keeps it in `attachment_text` (one row per attachment, `status` ok / none, a search index, deleted with the file by cascade). A file is read a moment after it is attached; a file attached earlier is read the first time Ask looks at its note (6 at a time, the rest in the background; `filesPending` tells the screen). Photos, scanned PDFs, old .doc/.ppt and files over 25 MB have no text (`none`, not retried). Ask's word search also looks in file text (ranked a little below note text), and each note read for an answer brings the parts of its files that match the question (`fileExcerpt`, ~3000 characters per note, 12000 when asking about one open note), labelled `FILE "name"`; files with no text are named as not read so the model does not guess. File text is data like note text, and is sent to the AI service with the question. Meaning-based search still covers the note text only; the list's search box does look inside file text (a plain substring match like the rest of the box, `noteQuery.js`; searching also starts the background read of files attached before this existed). The open note's files carry `readable` (true / false / null = not looked at yet) for the tooltip. Tests: `noteFileText.test.js`, the "reads inside attached files" route test.
- **Attached files**: up to 20 per note, any PDF, image, text, CSV or Office document up to 50 MB, using the shared attachment storage and policy (`server/utils/attachments.js`: allow-list, disguised-executable check, per-person quota; table `attachments`, `entityType` `note`, `entityId` = the note, no FK). `POST /api/notes/:id/attachments` (owner and count checked *before* the upload is read, so a refused request writes nothing); open and remove are the shared `GET/DELETE /api/attachments/:id`, whose owner check for `note` goes through `notes.user_id`. `GET /api/notes/:id` carries `attachments`, the list carries `attachment_count`, and `q` search also matches a file name and the text read from it. Attaching is filing (`updated_at` is left alone). Screen: `NoteFilesStrip.jsx` under the tags (Attach button, chips that open or save, Yes/No remove), drop files anywhere on the open note, paste files into the text (`useNoteAttachments.js`, pure helpers in `noteAttachments.mjs` kept equal to the server's limits by a test). **Recycle bin**: deleting a note leaves its files on disk and in `attachments` (the bin payload holds `attachmentIds`; the files cannot be opened while the note has no row); a restore points them at the note again (new id or old); when the bin item is gone for good (30 days, delete forever, empty bin) the new optional adapter hook `discard(db, userId, payload)` (see `docs/recycle-bin.md`) removes the files and rows. Removing a single file is permanent (not binned). Not read by Ask your notes or the AI actions.
- **Repeating reminders** (`server/services/noteRepeat.js`, `notes.remind_repeat` none|daily|weekdays|weekly|fortnightly|monthly|yearly, `remind_tz`, `remind_day`): the Repeat choice in the reminder box. Every step is made on the person's local calendar in the zone the browser sent (`Intl` zone, `UTC` if it sends nothing valid), so 9 am stays 9 am across daylight saving; monthly and yearly keep the day of the month it was set on (the 31st becomes the 28th, then the 31st again; 29 Feb becomes 28 Feb in a common year). **Done** on a repeating reminder moves `remind_at` to the next time after now (`advanced: true`, `reminder_done_at` stays null) instead of ending it; **Remove the reminder** or choosing Does not repeat stops it. The five-minute job first runs `advanceRepeating`: one nobody marked done whose next time has arrived moves on to the *latest* time that has come (due once, not once per time missed; the update only ever moves forward) and its email is then sent as usual (never more than a day late). Snoozing keeps the repeat (a stale screen that does not send `repeat` keeps what the note has); a snooze or time change restarts the schedule from the time you pick. No custom schedules (first Monday...) and no end date. `rotate-ccw` icon on the chip; the email says it repeats. The recycle bin keeps the repeat. Tests: `noteRepeat.test.js` (date maths incl. DST, month ends, catching up), the job and route tests.
- **Reminders**: one per note (`notes.remind_at`, `remind_email`, `reminder_sent_at`, `reminder_done_at`). The clock button beside project/client sets it (quick times or a date and time, optional "also email me"). When it falls due the note shows under **Reminders due** at the top of the list (the browser decides this from the date, so it works with no server job) with a Done / Snooze banner; `PUT /api/notes/:id/reminder`, `POST /:id/reminder/done`, and `?reminder=due|upcoming|any` on the list (also part of saved views). Emails: `server/cron/noteRemindersCron.js` every five minutes (skipped where `DISABLE_EXTERNAL_CRON` is set) runs `runNoteReminders` in `server/services/noteReminders.js`: it claims each due reminder in the database first (`FOR UPDATE SKIP LOCKED`), mails the person's own login address once, puts a failed one back for the next run (not after a day late), and tells the Suggestions inbox when a send fails. Reminders are filing, so they do not change `updated_at`, and they do not repeat.
- **Ask your notes**: the speech-bubble button opens a chat that answers from the person's own notes only, with the notes it used shown as numbers to open (`AskNotesPanel.jsx`, `server/services/noteAsk.js`, `POST /api/notes/ask`, history in `note_qa`, newest 100). Three steps: a **plan** (light model: keywords, a date range, tags, a client or project, only ones that exist, checked in code), **find** (Postgres full-text search, `to_tsvector('english', ...)` with title and tags weighted above the text, prefix matching so "budgets" finds "budget"; if the filters match nothing it widens, then falls back to the most recent notes, and the answering model is told which happened) and **answer** (standard model, only the numbered notes, citations checked: a `[n]` outside the notes given is removed). The scope is All my notes, This list (the list's own filters, through the same `server/services/noteQuery.js` the list uses) or This note. Every query starts from the owner check, note text goes only into the question part of the prompt (never the instructions, and the prompt says it is data), and a question with nothing to read is answered without calling a model. About a dozen notes of up to 3,000 characters (30 shorter ones for a summary), 36,000 characters in all. **Meaning search** (`noteEmbeddings.js`): each note has one embedding (title + tags + the first 6,000 characters) in `note_embeddings`, stored as 32-bit floats in a `bytea` and compared in code, not with pgvector, so it works on any database and is tested here. The scope filters run in SQL first, so only in-scope vectors are loaded. A question is embedded with the plan's keywords; notes under 0.4 cosine similarity, or more than 0.15 behind the best, are not matches; the word hits and meaning hits are merged by reciprocal rank fusion. An embedding is stale when the note's text changed (`content_hash`, md5 of title + text) or another embedding model made it (`source`); stale notes are mended 15 at a time while a question waits, the rest in the background, and a note ~20 seconds after it is saved. With no embedding model set up, or if it fails, Ask quietly uses words only. The two thresholds are first guesses: tune `MIN_SIMILARITY`/`BAND` against real questions. Long notes are embedded from their start only (no chunking yet). **Linked records / mud map** (`noteRelated.js`, the Linked records switch, on by default): around the notes read, it gathers their project and client (and the question's own named client/project), the open tasks (and ones finished in the last 30 days) on those projects/clients, their deals and recent contact (not the system rows), as keyed records `C1 P1 T1 D1 A1`. The answering model reads them (as data) and may cite them like notes; a key it was not given is stripped. The screen shows them as "Around these notes", an outline of client > project > tasks, with links to open each and the notes filed on it. Everything is by `"userId"`; contact history only through the person's own clients; stored with the answer in `note_qa.related`.
- **Recently deleted**: deleting a note, a template or a saved view goes through the shared recycle bin (`docs/recycle-bin.md`) for 30 days, with Undo in the toast and a Recently deleted window; the same items show in Settings → Recycle bin.

## Same conventions as the other tools (Video Tools, Measurements)

- **Tooltips**: the shared `components/Tooltip.jsx` on every control, never a native `title=""`. The wording is in one file, `client/src/pages/notes/noteTips.mjs`; add a tip there when you add a control.
- **(i) box**: `ToolInfoModal` "How Notes Works" (words in `notesInfo.mjs`), opens once per browser (`vault_notes_info_seen`), reachable from the (i) beside the title.
- **Tour**: `client/src/utils/tours/notesTour.js` (Shepherd, 15 steps, key `vault_tour_notes_completed`), the compass beside the title, and Settings -> Tours -> Notes Tour (`/notes?tour=1`). Steps point at `data-tour="notes-..."` attributes; on a phone the tour closes or opens a note as the step needs and creates nothing.
- **Guide chat**: `NotesTutorChat` (shared `TutorChat`), `server/services/notesTutor.js`; update the `CATALOG` and `notesTools.mjs` together.
- `client/src/pages/notes/noteTips.test.mjs` enforces all of this: no native titles, every tip used, every tour step points at something real, the step count is right, the Settings card and the guide exist.

## Rules worth remembering

- A note's tags, pin, reminder and filing (project/client) are *filing*, not editing: they do not change `updated_at`.
- `project_id` and `client_id` are checked to be the caller's own on every write.
- `notes.daily_date` and its index are left over from the removed daily note (removed 2026-10-24: nothing reads or writes them; old daily notes are ordinary notes, some still tagged `daily`). Dropping the column is irreversible, so it was kept.
- Named routes before `/:id` in `notes.js` (`/tags`, `/templates`, `/options`, `/voice`).
- When a feature or control changes, update `notesTools.mjs` and the guide `CATALOG` in `server/services/notesTutor.js` together (a test fails if they drift).
