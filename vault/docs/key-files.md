# Key files reference

Moved out of CLAUDE.md. Detailed per-file/per-tool notes. CLAUDE.md keeps only a short index.

- `server/index.js` — Express entry, route registration order matters (shared routes before requireAuth)
- `server/db.js` — all tables in one file; every statement idempotent (`IF NOT EXISTS`); runs on every boot
- `server/middleware/auth.js` — 32-byte hex token lookup in `auth_sessions` + `requireAdmin` guard + `requireFeature`/`loadFeatureAccess` (workspace flags narrowed by per-user `featureOverrides`)
- `server/routes/admin.js` — admin dashboard stats/monitor + user management endpoints + per-user feature-access endpoints
- `server/config/featureAccess.js` — `FEATURE_ACCESS_DEFAULTS`/`FEATURE_ACCESS_KEYS`, `flagsFromSettingRows()`, `applyUserOverrides()` (per-user narrowing, see **Feature access**)
- `server/routes/chat.js` — `buildSystemPrompt()`, prompt caching, SSE streaming, model routing
- `server/services/modelResolver.js` — **`getModelsForUser()`**: resolves **`light`** / **`standard`** / Gemini / DeepSeek from Settings (see **Model selection**)
- `client/src/hooks/useModels.js` — loads **`vault_models`** + **`default_model`** + **`branch_eval_model`** via `/api/settings`
- `client/src/utils/apiClient.js` — authenticated fetch wrapper; **use this for all `/api/` calls**
- `client/src/store/authStore.js` — Zustand auth (token, user); persisted
- `client/src/store/processingStore.js` — global long-running operation state; drives `ProcessingModal`
- `client/src/components/ProcessingModal.jsx` — **global blocking overlay** for slow operations; rendered once in `App.jsx`
- `client/src/components/ChatListPanel.jsx` — ChatGPT-style floating chat list (opened from the sidebar's **Search chats** button / the collapsed rail): New chat, search, Recent/Pinned, group by date or project, click-outside/Esc to dismiss. Data from `GET /api/chat/all-history` (newest 300); search covers each chat's title, first question, last reply and project name — not every message. **Pinned = the existing `sessions.starred` flag** (`PATCH /sessions/:id/star`, owner-checked), no new column. Grouping/search logic is pure in `client/src/utils/chatPanelGroups.mjs` (`node client/src/utils/chatPanelGroups.test.mjs`).
- `client/src/hooks/useDraggable.js` + `client/src/utils/dragPosition.mjs` — **drag any floating element out of the way** (mouse/touch, stays on screen, position remembered per browser, double-click the handle to reset). Used by the shared guide chat `components/tutor/TutorChat.jsx` (Finance + Video Tools: both the round button and the open chat). Use it for every new fixed button/panel; see **`client/DESIGN.md`** "Shared components". `npm run test:drag`.
- `client/src/components/SettingsNav.jsx` + `client/src/utils/settingsGroups.mjs` — **Settings menu**: grouped list down the left (You / AI and tools / Workspace / Layout / System), search box, one dropdown on a phone, tooltip per section. `SETTINGS_GROUPS` is the single list for the menu and the allowed-tab check; **add a new Settings tab there** (with an `admin` flag if members must not see it), then add its `{tab === '…' && …}` block in `SettingsPage.jsx`. `npm run test:settings-nav`.
- `client/src/components/Dialog.jsx` + `client/src/hooks/useDialogBehavior.js` + `client/src/utils/dialogFocus.mjs` — **the one modal shell: every dim-overlay modal is a `<Dialog>`**. Standard form: `title`, `footer`, `size`, `bare`, `role="alertdialog"` for destructive confirms. **`raw` form keeps a modal's own look** (`overlayClassName`/`overlayStyle`, `panelClassName`/`panelStyle`, any other prop lands on the panel, `panelRef` for a modal that scrolls or measures its panel; leave `onClose` out for a blocking prompt and the background and Escape do nothing). Either way you get role/name (the heading names it), focus moved in and trapped, Escape (newest dialog only), background click, page scroll lock, focus returned to the opener. Do not hand-roll a `fixed inset-0` modal. A click-away layer that is not a modal (menus, dropdown catchers) is not a Dialog. `useDialogBehavior` / `attachDialogBehavior` are the building blocks. `npm run test:dialog`.
- `server/routes/appVisits.js` + `client/src/components/AppUsagePanel.jsx` — **Which tools get used** (Admin dashboard, below Errors): the header trail's section id is counted once per section per 30 minutes (`POST /api/app-visits { key }`, table `app_visits` = person, day, key, count; nothing about the page), and `GET /api/admin/app-usage?days=` feeds a table of opens, days used and last used, plus a list of menu tools never opened in the period (read from the nav catalog, so a new tool appears automatically). Counting began when this shipped. This is the evidence for deciding what to prune or move to a Lab (review item P2 #9).
- `client/src/utils/popupQueue.mjs` + `client/src/store/popupStore.js` + `client/src/hooks/usePopupSlot.js` — **popups that appear by themselves take turns**: morning digest, task reminder, home-office hours prompt, reflection reminder. A new self-appearing popup calls `usePopupSlot(id, wantsToShow)` (before any early return), renders only when it returns true, and gets a place in `POPUP_PRIORITY`; never stack a second fixed popup. `npm run test:popups`. Also shared: `components/Skeleton.jsx` (loading placeholder) and `components/EmptyState.jsx` (what an empty list says + the next step); use them instead of a bare "Loading..." / "No items".
- `server/routes/attention.js` + `server/services/attention.js` + `client/src/components/NeedsAttention.jsx` — **Needs attention**: the one ranked list of things waiting on the person, at the top of Home and of the mobile dashboard (`GET /api/attention`). Sources today: overdue invoices (Finance), overdue and due-today tasks, note reminders due, invoices waiting in Invoice Review (Inbox Intel), new Suggestions; each is its own query filtered by the caller's id and feature switch, a failing source is left out, and the list renders nothing when empty. Ranking and wording are pure in `services/attention.js` (`npm run test:attention`). **To add a source: add a query in the route and a line in `buildAttentionItems` (with a test), not a new banner.** The older banners (task reminder modal, morning digest, WFH prompt) are not retired yet.
- `client/src/config/appNavigation.js` + `client/src/utils/navTrail.mjs` — **the one navigation catalog.** Apps menu, sidebar workspace links, top-bar quick links (`TOP_BAR_LINKS`: Tasks, Chat History, Notes, Settings), the header trail (`Project Vault / Group / Page`, a back arrow on phones, and on a detail page such as `/clients/12` the page name links back to its front page) and the Ctrl/Cmd+K app list all read it. **Active state is by whole path segment** (`isPathActive`): a section stays lit on its detail pages and `/clients` never lights `/client-projects`; an item whose pages live under a different folder sets `activeUnder` (Student -> `/student`). The phone menu and home tiles in `utils/mobileConfig.js` keep their own order (people reorder/hide them) but **any catalog item they do not list is added automatically at the end** (with its feature switch via `GENERATED_NAV_FEATURES` / `FEATURE_BY_TILE_ID`; admin-only items and external links are skipped), and their NAMES must match the catalog: `npm run test:nav` fails on drift or a gap. Before this, Talk, Client work and Email Follow-Up had no phone entry. Add a page to the catalog (not to Layout) and it gets a menu entry, an active state and a trail.
