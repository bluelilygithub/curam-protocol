# Features reference

Moved out of CLAUDE.md. Per-feature behaviour notes.

**Notes is the foundation tool** (2026-10-24): where things are written down first, then filed (project, client, tags), searched (words and meaning, including inside attached files), reminded, turned into tasks, and worked on in Chat. It is first in the Workspace group, in the sidebar's workspace links and in the landing-page choices. Chat works *on* Notes: a chat can read the matching notes when **My notes** is switched on for it (off by default, per chat; `server/services/noteContext.js`, shows which notes it used under each reply), and any reply or a whole chat can be saved to Notes (`client/src/utils/chatToNote.mjs`). **Talk it through** (`/talk`, `docs/talk.md`) is the spoken version: ask out loud, hear the answers, and the ended conversation becomes a note with a summary. Docs: `docs/notes.md`.

**Notes** (see Key Files and `docs/notes.md`) · Projects · Folders · Chat (project + general) · Files (RAG) · Memory · **Suggestions inbox** · Pinned URLs · **Document redaction** · Tasks (list/board/calendar/matrix, file attachments, one-way `.ics` calendar export) · Goals (OKR-lite) · Chat History · Web Search (`@search`, Brave/Serper/SerpAPI) · Gmail integration · Google Calendar · Google Drive backup · News Digest · Finance · **CRM** (contacts, deals/pipeline, touchpoints with channel filter + file attachments + task follow-up bridge, Gmail search — internal key "clients") · Admin dashboard + user management · Password reset · Shared task public links · **Student** (Quiz + Cards + Saved decks) · **Shares** (portfolio tracker) · **Product Scout** (Amazon comparison agent) · **Video Tools** (ffmpeg + FAL generate) · **YouTube** (search + favourites + history, no download — see `docs/youtube-agent.md`) · **Recipes** (leftover cooking assistant) · **Google Ads** (site scrape + keywords / RSA) · **SEO** (crawl + per-page recommendations) · **Search** (Google Search Console queries/pages) · **HTML** (Lighthouse / PageSpeed) · **AI Visibility** (AI crawler access, no-JavaScript readability, JSON-LD, simulated answers) · **Property Scenario** (mortgage / property calcs + CDR + document insights) · **PDF Tools** (merge/split/rotate/watermark, AcroForm field designer, Office↔PDF, Drive↔PDF) · **Font Customizer** (search an OFL Google Font, adjust real structural properties — stem thickness, width, ascender/descender, counter width, kerning — see the actual transformed font via debounced server-side preview, download a real renamed `.ttf`/`.woff2`/`.otf`; single screen, no client-side approximation) · **CSS** (non-technical CSS editor, internal key "restyle" — built-in demo page, upload/paste HTML + reorderable CSS, sandboxed live preview, click-to-edit property panel incl. text enhancements + animation presets, voice or plain-English AI requests, save pages to revisit later, PostCSS auto-fix/flags, no CSS jargon in any UI copy) · **Browser Agent** (live-streamed headless-Chromium form filling that never submits — see below) · **Measurements** (unit converter + formula library + PDF/photo measurement scanner, voice on every input, fully in-browser — see `docs/measurement-converter.md`)

**Browser Agent** (`/browser-agent`): Live-streamed headless Chromium (CDP screencast) driven by an Anthropic tool-use loop to fill forms on a named site — booking/enquiry forms, saved-login sign-ins — and stop. It never submits: submit/pay/sign-in buttons are blocked in code, and a Playwright network-route guard blocks any form POST while the agent has control; it always ends by handing the filled form to the user to review and send themselves. Profile (name/phone/email/address) and saved site logins (encrypted, filled server-side, password never reaches the model) live on their own Settings page. Conversation memory persists across follow-up instructions in a session; Clear session wipes it. Pause/Resume/Take over give three levels of interruption. Presets save reusable instructions; Archive keeps every past run with its full step log, outcome, duration and any error screenshots. Feature flag `browserAgent`. Docs: **`docs/browser-agent.md`**.

**Document redaction** (`/document-redaction`): Privacy-preserving DOCX redaction. Local LLM proposes candidates → HITL approve/reject/edit → synthetic apply (`redacted.docx` + `sanitized.pdf`) → local compare / leftover scan → HITL₂ → frontier residual-risk analysis on **sanitized PDF only** (entity map never leaves the machine) → selective frontier apply (shared apply pipeline on redacted base) → three-way compare → final approve + INTERNAL-ONLY audit trail. Feature flag `documentRedaction`. Model card `document-redaction-agent`. Docs: **`docs/document-redaction-agent-architecture.md`**.

**Finance** (`/finance`): Real double-entry bookkeeping for a sole trader, not just Invoices/Quotes — every posting goes through a shared journal helper that throws on any debit/credit imbalance, so the books stay balanced by construction. Full tab list: Dashboard, Invoices, Quotes, Suppliers, Expenses, Documents, Drawings, Vehicle/Home Office, Assets, Recurring, Wages, Interest, Journal, Accounts, Codes, BAS, Position, Balances, Reports, Settings. Covers chart of accounts, wages vs owner's drawings, vehicle/home-office ATO deduction calculators (cents-per-km/logbook, fixed-rate/actual-cost, method locked per financial year), an assets register with real depreciation (immediate/low-value-pool/prime-cost/diminishing-value) including purchase journal + GST split + disposal, recurring entries, manual journal, cash-basis BAS/GST lifecycle (open→reconciled→lodged→paid), and the FY pack (PDF + Excel + documents zip) as the single accountant hand-over. **Reports tab** (grouped): *Statements* (P&L, P&L Comparison, Balance Sheet, Cash Flow Statement, Trial Balance, General Ledger) · *Receivables & Payables* (Aged Receivables, Aged Payables, Customer Statements with PDF, Invoice Status) · *Sales & Purchases* (Sales by Client, Purchases by Supplier, Expenses by Category) · *Tax & Compliance* (GST Summary, BAS Worksheet, Depreciation Schedule, Drawings & Wages, Tax Time Summary) · *Planning & Control* (Budget vs Actual with an in-page budget editor, Audit Trail, Charts). Since 2026-10-13: Aged Payables ages real supplier bills (Accounts Payable + card purchases, due/settled dates); the Audit Trail is a trigger-written field-level change log (`fin_audit_log`); the BAS Worksheet covers G2/G3/G4/G13/G14/T7 (invoice-line GST codes, input-taxed expense flag, per-quarter PAYG instalment) and the BAS payment journal clears W2; GST basis is a Settings choice (cash/accrual, locked once a quarter is reconciled). Accountant hand-over (2026-10-13): Finance → **Documents** evidence library (`server/routes/financeDocuments.js`, tables `fin_documents`/`fin_document_links`), eight new reports (Income Received, Tax Payments & Credits, Cash Book, Capital & Related Parties, Expense Listing, Things to Review, Chart of Accounts & Codes, Documents Index), account/code mapping for the accountant's labels, and **Reports → Export FY pack** (PDF + Excel + zip; `server/routes/financePack.js`, `server/services/financePack/`). Details and remaining limits at the end of **`docs/finance.md`**. **Gotcha fixed 2026-09-30:** P&L/Balance Sheet/Trial Balance previously summed journal lines outside the chosen date range (date filter sat in a `LEFT JOIN`) — any report filtering by entry date must inner-join entries or guard the sum. Route: `server/routes/finance.js` (large — see **`docs/finance.md`** for the accounting design, invariants, and known gaps before touching it); extra reports in `server/routes/financeReports.js`. Client: `client/src/pages/FinancePage.jsx` + `client/src/pages/finance/ExtraReports.jsx`.

Invoices/Quotes specifically (`fin_invoices`/`fin_invoice_items`, `docType` distinguishes): row actions Send/Resend (opens send modal, PDF attached via `invoicePdf.js`), Edit, Convert (quote→invoice), Paid, Del, PDF download, **Activity** (opens the same detail modal used by clicking a row — shows `fin_invoice_send_log` history: sent-to, cc, provider, messageId, pdfAttached, ok/error). Shared `POST /invoices/:id/send` route always CCs the workspace `fin_admin_email` setting (Settings → Finance) on every send/resend, invoice or quote — logged in `fin_invoice_send_log.cc`; two failed sends for the same document within 24h also raises a Suggestions-inbox alert.

**Video Tools** (`/videos`): Phase 1 video suite mirroring Graphics — grouped sidebar arranged by what you are doing (Make / Edit video / Titles and captions / Audio / Export and convert / Library and info — `TOOL_GROUPS`; add a new tool to the group where a person would look for it, then add its `TOOL_TIPS` entry and tutor `CATALOG` entry, which tests enforce). **Long video jobs run in the background** (`server/services/videoBackgroundJobs.js`: POST answers 202 `{jobId}`, the page polls `GET /api/videos/jobs/:id`; one job per person; a request left open past ~5 minutes is killed by the gateway while the server keeps working; the page tolerates missed progress checks, can cancel, and resumes via a banner; ffmpeg runs under `nice`; read the `[videos/<tool>] job ...` timing lines in the Railway log). Use `runJobVideo` / `startBackgroundJob` for any new tool that can take more than a minute or two. **Intro and ending** (Compose; id/API `extend-ending`): hold the first and last frame, an optional title over each (opening fades away as the video moves, closing fades in as the music fades), music under both and voice that plays once after the opening hold (`POST /api/videos/extend-ending`, `server/services/extendEnding.js`, `videoEndCard.js` `applyIntroCard`; needs the voice and music as separate FILES, sound already merged into a video cannot continue). **Mix audio** (Compose): voice + background music -> one audio file with ducking, fades and loudness levelling (`POST /api/videos/mix-audio`, `server/services/audioMix.js`, reuses `music/musicFit.js`). **Title card** (Titles and captions): the opening/closing message card shown between any start and end time in the middle of a video (`POST /api/videos/title-card`, `server/services/titleCard.js`, `windowTiming`/`windowTitleStage` in `videoEndCard.js`); length and sound untouched; background job. **Replace a section** (Edit video): swap the picture of one section for a clip of EXACTLY the same length; original soundtrack copied untouched; same total length; transitions inside the section; background job (`POST /api/videos/replace-section`, `server/services/replaceSection.js`). **Video Tools tutor** (graduation-cap button, `TutorChat.jsx`, `POST /api/videos/tutor`, `server/services/videoTutor.js`): mini chat that recommends steps across the real tools, or says a tool is missing / the job is beyond Video Tools; `CATALOG` in `videoTutor.js` must be updated whenever a Video Tools tool is added or removed (a test enforces it). **Isolate voice** (Optimise): voice out of a recording with background music — AI (Demucs on Replicate) or free ffmpeg filter; `POST /api/videos/isolate-voice`, `server/services/voiceIsolation.js`. **Trim audio** (Transform): keep or cut out a part of an MP3 etc. via `POST /api/videos/trim-audio` (`planAudioTrim`/`trimAudioArgs` in `videoFfmpeg.js`; stream copy by default, re-encode only for fades/middle cuts). **Audio → transcript** (Optimise): audio file (MP3 etc.) → editable plain text or timestamped SRT via `POST /api/videos/transcribe-audio` (hosted: shrunk to speech MP3 → Gemini; local: whisper-cli text only); with timestamps it can go to Caption studio or `POST /api/videos/audio-to-video` (audio → flat-colour video with the captions burned along the bottom; user sets shape, screen colour, font, size, colours). **Script to captions** (`ScriptTimer.jsx`, `POST /api/videos/time-script`, `server/services/scriptTiming.js`): a script with no timestamps is matched to the media's transcribed speech, or spread evenly as a fallback, to make timed captions. **Voice directions**: every tool with settings has a "Tell it what to do" box (editable transcript + Apply) → `POST /api/videos/voice-command` (`server/services/videoVoiceCommand.js`). All H.264 encodes must set `-pix_fmt yuv420p` (test enforces); Clip sends length via `-t`, with a "Keep original quality" stream-copy option. **Generate** expands brief via `light` tier then **Replicate** (`minimax/hailuo-2.3`, default when `REPLICATE_API_TOKEN` set) or FAL fallback. **ffmpeg** tools: clip, convert/compress, join (+ crossfade), reframe/crop, speed, mute/replace audio, overlay/watermark, extract audio, annotate (drawtext), probe, thumbnail. **Caption studio** — upload or library video + styled SRT (font, weight, size, colour). **Saved media** — save tool results (video/image) + transaction JSON to `video_library` (disk + DB), preview, delete, re-caption later. Local dev: optional whisper-cli transcribe; hosted → paste SRT. Feature flag `videos`. Docs: **`docs/video-tools.md`**. Dockerfile installs `ffmpeg`.

**Recipes** (`/recipes`): Cooking assistant in Content tools. **Leftover recipes** — ingredients in → four cards → full recipe (steps, nutrition, links, auto dish photo). **Recipe by name** — Basic / Advanced / Master with accessible ingredient swaps. **Grocery prices** — "Get prices" inline under any open recipe (also standalone in Shop) → Coles/Woolworths prices **sourced from live search** (Google Shopping via Serper/SerpApi, or `site:` organic fallback), each row cites its source link; unmatched items show "Not found" + manual search link, never a guessed price. Requires `SEARCH_API_KEY`; no text model needed for pricing. Save to **`recipes`** table with tags. Text: `light`/`standard` tiers; images: **`graphicsImageService`** + **`graphics_model`**. Feature flag `recipes`. Docs: **`docs/recipes.md`**.

**PDF Tools** (`/pdf`): Stateless PDF toolkit — every tool posts a `dataUrl` (base64 PDF/image), gets a `dataUrl` back; no DB table, no persistence. Merge, split (page ranges `1-3,5,7-9`), rotate, watermark, page numbers, metadata read/write, image↔PDF, Office↔PDF (LibreOffice headless: DOCX/XLSX/PPTX/ODT/RTF/CSV/TXT etc.), Google Drive↔PDF (Docs/Sheets/Slides export or binary Office re-upload, reuses `gmail_tokens` OAuth), AcroForm inspect/fill/flatten/**field designer**, and chat over an uploaded file's extracted text. Not currently behind a feature flag. Route: `server/routes/pdf.js`. Docs: **`docs/pdf-agent.md`**.

Custom fonts on a *live* AcroForm field (`field.updateAppearances`) render as Helvetica in Chrome/Edge/Adobe Reader regardless of correct embedding — inherent viewer limitation. Fix used everywhere: stamp the value as static page content (`page.drawText()`, same as watermark/page numbers) instead of a fillable field — immune to that substitution since content-stream text isn't re-rendered by the viewer. **Field designer**: a `text` field with a value typed in at design time stamps rather than becoming a field. **`/fill`** defaults to the same (`flatten: true` — stamps each value at its field's position and removes the field; `flatten: false` for old live-field behaviour). Font picker is pdf-lib's 14 built-in standard fonts (Sans Serif/Serif/Monospace) everywhere a live AcroForm field is possible (dropdown, empty fillable text field); a **Script** group (10 manually-verified Google Fonts, fetched as TTF via `fetchScriptFontBytes()`) is additionally offered wherever the stamp path is guaranteed (Fill Form's picker, a field-designer `text` field) — never on `dropdown`, which stays a live field.

**Google Ads** (`/google-ads`): Content-tools agent with its own projects (not Vault chat projects). Paste a URL plus **what they sell** (offer is ground truth) → SSRF-safe scrape → **`standard`** model builds 100 Google Ads keywords, 100 negatives, and RSA copy. Ads tab can generate RSA (15/4) or a 10-headline / 10-description pack. Lists follow the offer if the live page is a different industry. Copy or CSV for Ads Editor. Tables: `seo_projects` (includes `offer`), `seo_artifacts`. API: `/api/google-ads`. Feature flag `googleAds`. Docs: **`docs/google-ads-agent.md`**.

**SEO** (`/seo`): Crawl a URL (1–40 same-origin HTML pages, default 25) for organic campaigns — indexation, SERP titles/descriptions, thin/duplicate URLs, schema, hreflang, sitemap vs crawl, click depth, internal links. Not Lighthouse (use **HTML**), not Ads (use **Adwords**), not query data (use **Search**). Table: `seo_audits`. Flag `seo`. Docs: **`docs/seo-agent.md`**.

**Search** (`/search-console`): Google Search Console — OAuth (`webmasters.readonly`), 28-day queries, pages, and query/URL cannibalisation. Tables: `gsc_tokens`, `gsc_snapshots`. Flag `searchConsole`. Redirect: `GSC_REDIRECT_URI` or `{APP_URL}/api/gsc/callback`. Docs: **`docs/search-console-agent.md`**.

**Page speed** (`/html`, nav label "Page speed"; internal key and route unchanged): Google Lighthouse via PageSpeed Insights (mobile **and** desktop). Performance, accessibility, best practices, Lighthouse SEO, lab metrics, real-visitor field data, opportunities with file URLs, failed checks, a prioritised Actions tab with ticks and notes saved on the run, a client-ready PDF report, **Copy for AI** (a ready-to-paste improvement prompt containing the chosen device's findings and what to weigh up), **Copy mobile + desktop** (the raw developer brief for both devices) and **Copy action list**. Table: `html_audits`. Flag `html`. Requires `PAGESPEED_API_KEY`. Docs: **`docs/html-agent.md`**.

**AI Visibility** (`/ai-visibility`): Audits one public page for AI assistants rather than Google rankings. robots.txt is parsed properly and checked per AI crawler (GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot, PerplexityBot, Google-Extended, Applebot-Extended, CCBot, Bingbot and others), naming the exact rule that blocks each one. The raw HTML is compared with the same page rendered in Chromium to show how much of the offer exists only after JavaScript. JSON-LD is validated entity by entity (Organization, LocalBusiness and its subtypes, Product, Offer, FAQPage, Article, BreadcrumbList, WebSite, Service), including the properties answer engines quote. Buyer questions (supplied, or four generated from the page) are searched live through the existing Brave/Serper/SerpAPI key, answered by a connected text model, then scored on three separate outcomes — found in the search results, named in the answer, linked in the answer — plus a documented heuristic check of supplied key facts (numbers are matched with their units). Saved runs, on-page report, **Copy for AI** (Markdown), a PDF and the round **AI Visibility guide** chat. Table: `ai_visibility_audits`. Flag `aiVisibility` (preview). Docs: **`docs/ai-visibility.md`**.

**Web Extractor** (`/web-extractor`): Pull content from any public URL, three modes — **Article content** (jsdom strips nav/header/footer/sidebar/ads/comments/images, returns readable text + title/byline, downloadable as PDF via `server/services/webExtractorPdf.js`), **Extract images** (dedup'd `<img>`/`<picture>` + `og:image`, prefers lazy-load attrs `data-src`/`data-lazy-src`/`data-original` over placeholder `src`, absolute URLs, alt text; per-image download or "Download all" as zip), **Exact scrape** (original HTML with relative asset/link URLs rewritten absolute, inline styles/`<style>` untouched, rendered read-only in a sandboxed iframe). No persistence — stateless single-shot API. Uses the same SSRF-safe `htmlFetch.fetchHtml()` as Translate/SEO/pinned URLs; image downloads use a binary-safe SSRF-checked fetch (`webExtractorService.fetchBinary`, htmlFetch decodes everything as utf8 text so it can't carry binary). Flag `webExtractor`. Route: `server/routes/webExtractor.js`. Service: `server/services/webExtractorService.js`.

**Shares** (`/shares`): Personal share portfolio tracker. **Eleven tabs:** Portfolio · Trades · Cash · **CGT** · **Statements** · **Accountant pack** · Charts · News · **Questions** · **Thesis** · **Metals**. **Thesis** (2026-11-07) is a per-holding journal of assumptions and red lines with an AI check that never gives buy/sell advice — see **`docs/shares-thesis.md`**, which also covers the 9-step Shares tour (link beside the title, or Settings → Tours). **Roadmap:** the agreed plan, decisions and status live in **`ROADMAP.md`** — read it before starting Shares work.

- **CGT tab** — capital gains per purchase parcel in AUD (`GET /api/shares/cgt?fy=`, `server/services/sharesCgt.js` — pure calc, tested by `node server/services/sharesCgt.test.js`). **FIFO** matching (the Portfolio tab's Realised P&L uses average cost, so they differ); **trade date** (`tradedAt`, calendar day in the workspace timezone), never settlement; **12-month discount test excludes both the purchase and sale day** (bought 1 Jan 2025 → first eligible sale 2 Jan 2026); AUD figures used **as stored** (no FX re-conversion); 50% discount (individual), losses applied to non-discount gains first. Flags sells with no matching buy. FY selector + CSV export; no schema change. See **`docs/shares-cgt.md`**.

- **Statements tab (dividends only)** — upload a broker PDF statement (CMC Markets primary, broker-agnostic LLM extraction); **dividend lines only** are extracted and shown in a review queue — **nothing auto-applies**, every line needs explicit approve/edit/reject before it writes to `share_cash_ledger`. Trade/fee/interest/DRP extraction was **switched off 2026-09-20** (trade date/price matching against real statements was unreliable — likely upstream imprecision in manually-entered `share_trades`); `LINE_TYPES` is narrowed but the schema still supports all types, so re-enabling is a prompt + filter change once trade data is cleaned up. The CMC "Trading Account Statement" shows **net dividends only** (no withholding split). `server/services/sharesStatementImport.js` + `server/routes/sharesStatements.js` (`/api/shares/statements`, `aiLimiter`). Dedup across prior imports (hash), corrections flagged not auto-resolved, imports revertible (via `sourceImportId`). Full spec: **`docs/shares-statement-import.md`**.
- **Questions tab** — chat about your own portfolio; answers grounded only in stored data, cites numbers, never recommends buy/sell (`sharesAskService.js`, `share_qa`).
- **Metals tab** — gold purchase book (`metal_purchases`): total oz, cost, spot value, unrealised P&L; XAU/AUD spot history (`metal_spot_snapshots`) and drawdown alerts. Also feeds the **METALS & MINERALS** section of the Portfolio Note.
- **Dividends** — approved dividends land in `share_cash_ledger` (types: deposit, withdraw, dividend, interest, fee; `symbol` column set on dividends). **`amountAud` is always NET (cash received)**; gross / `withholdingTaxAud` / `withholdingRatePct` / `grossDerived` / `paidOn` sit alongside it. CMC shows net only, so gross is derived (US-listed default 15% assuming a current W-8BEN, override via settings key `shares_us_withholding_pct`; ASX 0%; unknown exchange left un-derived) and flagged "derived"; editable per dividend on the Cash tab. `paidOn` is the payment date — summaries use `COALESCE(paidOn, createdAt)`. Franking columns (`frankedAmountAud`, `frankingCreditAud`, `frankingPercent`) exist but nothing uses them yet. Portfolio tab: FY **gross** dividend tile (net + tax withheld in the sub-line) + rough yield; Charts: by-holding/by-month gross bars; Cash tab: gross − tax = net per dividend + per-type subtotals. See `docs/shares-statement-import.md`. `computeCashFromActivity()` treats deposit/dividend/interest as increases and withdraw/fee as decreases.

- **Charts tab** — observation-aligned analytics: portfolio vs benchmark day move, beat/lag movers, HWM drawdown alerts, 5-day trailing returns, allocation by sector proxy, relative performance from stored observations, earnings timeline, move heatmap, metals spot/book. See **`docs/shares-charts.md`**. API: `GET /api/shares/charts?days=1|7|30|90`.

- **Holdings + P&L:** `computeHoldingsAndRealized()` in `sharesPortfolio.js` processes trades chronologically (avg-cost method). Returns open holdings + realized P&L per sell. `buildDashboard()` fetches live quotes and returns `positions`, `realized`, `totalRealizedPnlAud`, `unrealizedPnlAud`.
- **Quotes:** Finnhub (`FINNHUB_API_KEY`) for NYSE/NASDAQ; Alpha Vantage (`ALPHA_VANTAGE_API_KEY`) for ASX. Frankfurter for USD→AUD. In-memory quote cache (15 min for user page loads) prevents burning Alpha Vantage's 25 req/day free-tier limit.
- **Cron schedules** (timezone = admin user's `user_timezone` setting, fallback `Australia/Sydney`): ASX snapshots 5 AM + 1 PM; US snapshots hourly 10:00–16:00 ET Mon–Fri; daily news briefings 4 AM; **Portfolio Note email 7 AM**; monthly summary 1st of month 4:30 AM. US poll also runs hourly shares drop/update emails to admins (metals spot + metals tables are daily-only — see `docs/shares-portfolio-note.md`).
- **Exchange filter:** cron passes `['ASX']` or `['NYSE','NASDAQ']` to `recordSnapshots()` so each run only calls the relevant quote API; stale cache covers the other exchange for the portfolio snapshot.
- **Timezone:** All date storage and cron scheduling use the admin user's `user_timezone` profile setting (read via `GET /api/settings/workspace-timezone`, which queries the first admin's `settings` row). Hardcoded `Australia/Sydney` was removed in favour of this dynamic lookup.
- **News tab — daily briefings:** `sharesNewsService.generateDailyBriefing()` fetches Finnhub company news (US) or web search (ASX), plus a Nasdaq market search, then makes one AI call (`callModel` → `standard` tier) producing per-stock paragraphs + `bullish/bearish/watch/neutral` signals. Stored with `type='daily'`. Auto-pruned after 45 days. Manual "Generate today" button triggers `ProcessingModal`. UI groups by date in an **accordion** — one day open at a time, most recent open by default, collapsed header shows signal badge and stock count.
- **News tab — 30-day summaries:** `sharesNewsService.generateMonthlySummary()` reads 30 days of daily briefings, sends to AI for trend + signal-accuracy review. Stored with `type='monthly_summary'`, never deleted. Triggered via "30-day summary" button (also uses `ProcessingModal`). Cron also runs on the 1st of each month.
- **Portfolio Note (daily email):** `sharesNewsService.generateObservation()` — structured analyst note (TOP LINE, MOVERS & CAUSALITY, SECTOR & MACRO, NEWS WORTH ACTING ON, RISK WATCH, DECISION TRIGGERS, ONE-LINER). Pre-computes portfolio day move, per-holding beat/lag vs SOX/Nasdaq/ASX proxies, and mover list before a 3-stage LLM pipeline. Records metals spot once and includes **METALS & MINERALS** when holdings exist. Stored `type='observation'`, emailed 7 AM + on manual observe/refresh. Full spec: **`docs/shares-portfolio-note.md`**.
