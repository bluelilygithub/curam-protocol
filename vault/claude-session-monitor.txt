  Build a Claude Code usage window tracker — two SVG donut gauges showing how far through                                 the 5-hour session window and the 7-day weekly cap window the user is.
                                                                                                                          ## What it does

  Claude Code enforces two independent usage windows:
  - **5-hour window** — starts from the first message of a session (not from hitting the limit).
    e.g. if you start at 6:00am and hit the limit at 9:00am, the reset is still at 11:00am.
  - **Weekly cap** — a separate 7-day rolling window. When this is exhausted, the 5-hour
    reset does NOT restore access — you wait for the weekly reset.

  The gauges are purely time-based, calculated from `new Date()` in the browser.
  No Claude Code API exists — this is estimation based on a configured start time.

  ## Core logic (copy this exactly)

  ```js
  const SESSION_HOURS = 5;
  const SESSION_MINS  = SESSION_HOURS * 60;
  const WEEK_DAYS     = 7;

  function parseHHMM(str) {
    const [h, m] = (str ?? '06:00').split(':').map(Number);
    return { h: h || 0, m: m || 0 };
  }

  function fmt12(date) {
    const h    = date.getHours();
    const m    = date.getMinutes();
    const ampm = h >= 12 ? 'pm' : 'am';
    const h12  = h % 12 || 12;
    return `${h12}:${String(m).padStart(2, '0')}${ampm}`;
  }

  function fmtDuration(mins) {
    if (mins >= 60) {
      const h = Math.floor(mins / 60);
      const m = mins % 60;
      return m > 0 ? `${h}h ${m}m` : `${h}h`;
    }
    return `${mins}m`;
  }

  // cfg = { daily_start: 'HH:MM', weekly_start_day: 0-6 }
  // weekly_start_day: JS day index — 0=Sun 1=Mon 2=Tue 3=Wed 4=Thu 5=Fri 6=Sat
  function computeWindows(cfg) {
    const timeStr    = cfg?.daily_start ?? '06:00';
    const startDay   = cfg?.weekly_start_day ?? 1;
    const now        = new Date();
    const { h, m }  = parseHHMM(timeStr);
    const windowMs   = SESSION_MINS * 60_000;

    // 5-hour window
    const firstStart = new Date(now);
    firstStart.setHours(h, m, 0, 0);

    let pct5h, sessionLabel, sessionSub;
    if (now < firstStart) {
      const minsUntil = Math.ceil((firstStart - now) / 60_000);
      pct5h        = 0;
      sessionLabel = `Starts in ${fmtDuration(minsUntil)}`;
      sessionSub   = `First session begins at ${fmt12(firstStart)}`;
    } else {
      const elapsed      = now - firstStart;
      const winIdx       = Math.floor(elapsed / windowMs);
      const winStart     = new Date(firstStart.getTime() + winIdx * windowMs);
      const winEnd       = new Date(winStart.getTime() + windowMs);
      const elapsedInWin = now - winStart;

      pct5h = elapsedInWin / windowMs;

      const minsLeft = Math.ceil((winEnd - now) / 60_000);
      sessionLabel   = `${fmtDuration(minsLeft)} remaining`;
      sessionSub     = `Window ${winIdx + 1} · Resets at ${fmt12(winEnd)}`;
    }

    // Weekly window
    const DAY_NAMES = ['Sun','Mon','Tue','Wed','Thu','Fri','Sat'];
    const dow       = (now.getDay() - startDay + 7) % 7;
    const dayFrac   = (now.getHours() * 60 + now.getMinutes()) / (24 * 60);
    const pctWeek   = (dow + dayFrac) / WEEK_DAYS;
    const daysLeft  = WEEK_DAYS - dow - 1;
    const weekLabel = daysLeft > 0 ? `${daysLeft}d remaining` : 'Last day of week';
    const weekSub   = `${DAY_NAMES[now.getDay()]} — day ${dow + 1} of 7 (resets ${DAY_NAMES[startDay]})`;

    return { pct5h, sessionLabel, sessionSub, pctWeek, weekLabel, weekSub };
  }

  ---
  SVG DonutGauge component (React — adapt to your framework)

  function gaugeColor(pct) {
    if (pct >= 0.85) return '#ef4444'; // red
    if (pct >= 0.65) return '#f59e0b'; // amber
    return '#22c55e';                   // green
  }

  function DonutGauge({ pct, label, sublabel, size = 160 }) {
    const r    = 46;
    const cx   = 50;
    const cy   = 50;
    const circ = 2 * Math.PI * r;
    const fill = Math.min(Math.max(pct, 0), 1);
    const color = gaugeColor(fill);

    return (
      <div style={{ display: 'flex', flexDirection: 'column', alignItems: 'center', gap: 12 }}>
        <svg width={size} height={size} viewBox="0 0 100 100">
          {/* Track */}
          <circle cx={cx} cy={cy} r={r} fill="none" strokeWidth="10" stroke="#e5e7eb" />
          {/* Progress arc — starts at 12 o'clock */}
          <circle
            cx={cx} cy={cy} r={r}
            fill="none" strokeWidth="10"
            stroke={color}
            strokeLinecap="round"
            strokeDasharray={circ}
            strokeDashoffset={circ * (1 - fill)}
            transform={`rotate(-90 ${cx} ${cy})`}
            style={{ transition: 'stroke-dashoffset 0.6s ease, stroke 0.4s ease' }}
          />
          <text x="50" y="47" textAnchor="middle" fontSize="16" fontWeight="700" fill={color}>
            {Math.round(fill * 100)}%
          </text>
          <text x="50" y="60" textAnchor="middle" fontSize="7" fill="#9ca3af">
            used
          </text>
        </svg>
        <div style={{ textAlign: 'center' }}>
          <div style={{ fontWeight: 600, fontSize: 14 }}>{label}</div>
          <div style={{ fontSize: 12, color: '#6b7280' }}>{sublabel}</div>
        </div>
      </div>
    );
  }

  ---
  Config persistence

  The user needs two config values:
  - daily_start — string HH:MM (24h), e.g. "06:00" — the time they typically start their first session
  - weekly_start_day — integer 0–6 (JS day index) — day the weekly cap resets (default Monday = 1)

  Option A — localStorage (simplest, no backend needed):
  const cfg = JSON.parse(localStorage.getItem('claudeSessionConfig') ?? '{}');
  // defaults:
  const daily_start      = cfg.daily_start      ?? '06:00';
  const weekly_start_day = cfg.weekly_start_day ?? 1;

  Option B — backend API (DB-backed, multi-device):
  - GET /settings/claude-session → { daily_start, weekly_start_day }
  - PUT /settings/claude-session body { daily_start, weekly_start_day }
  - Store as JSONB in a settings table keyed by user or org

  ---
  Wiring it together (React)

  export default function ClaudeSessionTracker() {
    const [windows, setWindows] = useState(null);
    const [cfg, setCfg]         = useState({ daily_start: '06:00', weekly_start_day: 1 });

    useEffect(() => {
      // Load config (from localStorage or API), then compute
      const saved = JSON.parse(localStorage.getItem('claudeSessionConfig') ?? '{}');
      const merged = { daily_start: '06:00', weekly_start_day: 1, ...saved };
      setCfg(merged);
      setWindows(computeWindows(merged));
    }, []);

    // Refresh every 30 seconds
    useEffect(() => {
      const id = setInterval(() => setWindows(computeWindows(cfg)), 30_000);
      return () => clearInterval(id);
    }, [cfg]);
    return (
      <div>
        <DonutGauge pct={windows.pct5h}   label={windows.sessionLabel} sublabel={windows.sessionSub} />
        <DonutGauge pct={windows.pctWeek} label={windows.weekLabel}    sublabel={windows.weekSub} />
      </div>
    );
  }

  Key facts to preserve in the UI

  - The 5-hour window starts from the first message, not from when the limit is hit
  - The weekly cap is independent — exhausting it means waiting for the 7-day reset even if the 5-hour window resets
  - Pinging Claude Code does NOT reset either window — both are consum







Claude Code uses a dual-layer usage system with two distinct windows that serve different purposes:

The 5-Hour Rolling Window (burst control)
The five-hour rolling window governs burst usage — effectively capping how many requests a user can submit within a given time frame. TrueFoundry Importantly, the timer doesn't reset based on clock time — it resets based on when you first accessed Claude Code. If you start a session at 2 PM, your new five-hour window opens at 7 PM, not at midnight. Usagebar
In terms of message allowances: Pro plans allow approximately 45 messages per 5-hour window, while Max 5x subscribers get 225 messages and Max 20x users get 900. Usagebar

The Weekly Cap (abuse prevention)
In addition to the 5-hour rolling windows, Anthropic enforces weekly rate limits that reset every seven days. These include an overall usage cap plus a separate weekly cap for Opus models. Portkey
The weekly limit is shared across all Claude usage — claude.ai conversations count toward it, Claude in your IDE counts toward it, and Claude Code counts toward it. Usagebar

Why both limits exist
The weekly cap and rolling window serve as guardrails, ensuring no developer or team can monopolize resources or circumvent fair-use policies by switching access points or stacking parallel sessions. Enforcing rate limits also deters scenarios such as account sharing, reselling Claude access, or deploying continuous scripts — in each case, unchecked usage would otherwise degrade service reliability for all users. TrueFoundry
Anthropic says the limits affect fewer than 5% of subscribers based on usage patterns. Portkey

What happens when you hit a limit
Extra usage allows individuals on paid plans to continue using Claude seamlessly after reaching their included usage limits — instead of being blocked, you can switch to consumption-based pricing at standard API rates and continue without interruption. Session limits reset every five hours as usual. Claude
You can monitor both windows at Settings > Usage in claude.ai, which shows progress bars for both your current session and weekly limits.
